# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — local dev server at `http://localhost:4321`
- `npm run build` — production build to `./dist/`
- `npm run preview` — preview the production build locally
- `npm run astro -- <args>` — Astro CLI passthrough (e.g. `npm run astro -- check`)
- `npm run optimize:images` — manually re-run the image optimizer (CI normally does this; see Image pipeline below)
- `npm run make:og` — regenerate the default `public/og-image.jpg` from `public/images/hero-illustration.webp` (the hero itself is video-only and no longer CMS-switchable to an image; that file is kept only as this script's `SOURCE`)
- `npm install` requires `legacy-peer-deps=true` (set in `.npmrc`) to resolve current Astro/React peer ranges — don't remove that setting without confirming install still succeeds.

There is no test framework, no linter, and no CI check configured beyond the image-optimization workflow described below.

## Origin

This repo was scaffolded to mirror the sibling `suleika-portfolio` project's technical foundation (Astro + Cloudflare + Keystatic + hand-rolled SEO/i18n/image-pipeline), then rebuilt section-by-section against a Codex Design handoff (`design_handoff_ana_beatriz_landing/` — not committed to this repo, kept only in the session that built it) for tattoo artist Ana Beatriz ("Samambaia Ana"). Where the two diverge, this file notes it explicitly rather than assuming familiarity with the Suleika repo.

## Architecture

**Rendering.** Astro with `output: 'server'` (astro.config.mjs) — every route is server-rendered on Cloudflare's edge via the `@astrojs/cloudflare` adapter (`imageService: 'passthrough'`). Nothing is statically prerendered.

**Single-page structure.** Unlike suleika-portfolio (multi-page), this is a single long page (`src/pages/index.astro`) with in-page anchors (`#work`, `#about`, `#book`, `#flash`) plus one separate route, `/flash`, for the full flash-design gallery + lightbox (the design handoff's version was a same-URL JS overlay; this is a real route instead — see README for why). `src/pages/en/*.astro` files are one-line wrappers that render the PT page component — `Astro.url` reflects the actual request URL through the component tree, so the same component renders correctly under either path without duplicated markup.

**i18n / routing.** Portuguese lives at `/`, English is mirrored under `/en/` (`prefixDefaultLocale: false`) — same mechanism as suleika-portfolio's DE/EN, renamed pt/en throughout (`ptOnlyPaths` where that repo has `germanOnlyPaths`, etc.). `src/middleware.ts` picks the language for ambiguous URLs: an explicit `?lang=` query wins and is remembered in a cookie, then the cookie, then `Accept-Language` — crawlers (matched by user-agent) always get the URL they literally requested and are never redirected. `/api/`, `/keystatic`, `/_*`, and anything with a file extension are skipped by this logic entirely. `src/i18n/ui.ts` holds short/structural UI strings (nav, a11y labels, form validation, section heading words) for both locales. Longer marketing copy (hero headline/intro, bio paragraphs, booking intro, footer tagline) is **not** in `ui.ts` — it's Keystatic-managed content (see below), matching how suleika-portfolio splits `ui.ts` vs. CMS singleton fields.

**Content model.** Two systems feed `src/content/`:
- **Keystatic** (`keystatic.config.ts`, `storage: { kind: 'cloud' }`) is the editor UI at `/keystatic`, backed by Keystatic Cloud. **The `cloud.project` slug is currently a placeholder** (`samambaia-ana-tattoo/samambaia-ana-tattoo`) — Keystatic will not authenticate until this project is registered on keystatic.cloud and the slug updated.
- **`src/content.config.ts`** defines the Astro content collections (`portfolio`, `flash`, `testimonials`, `faq`, `otherWork`, `singletons`) that read those same JSON files back out via `astro/loaders`'s `glob()` loader.
- Every singleton/collection starts with a read-only `howTo` field (`howTo()` in `keystatic.config.ts`: an `fields.object({})` with no subfields renders as just its label + description) holding a Portuguese "Como funciona" note for the client, and the `guide` singleton ("📖 Como usar o painel", pinned first in the nav) is nothing but such notes. Keystatic has no other place to show section-level help. Keep these notes in sync when a section's behavior changes.
- `/guia` (`src/pages/guia.astro`, assets + PDF copy in `public/guia/`) is a standalone Portuguese how-to for the client, linked from the `guide` singleton (`GUIDE_URL`). Not in the nav or sitemap, `noindex` via middleware, and exempt from the language redirect. Update it (and its screenshots/PDF) together with the `howTo` notes.
- The `portfolio` collection is a **fixed 8 slots** (`order: 0-7`) — the asymmetric mosaic grid layout (column/row spans on desktop, aspect-ratio/offset on mobile) is hand-tuned in code (`DESKTOP_SPANS` / `MOBILE_SPANS` in `index.astro`), ported from the design handoff's own hardcoded layout arrays. The CMS only ever swaps which photo occupies which of the 8 slots — adding/removing a slot needs a code change, not just a CMS edit. Slot 7 is also the scroll-zoom source image (see below).

**Reveal animations.** `src/components/LetterReveal.astro` splits heading text into per-character `<span class="letter">` elements with a `--d` stagger-delay custom property, ported from the handoff's `letterReveal()`. Each word's letters are nested inside their own `display: inline-block` wrapper — **this matters**: without it, every letter is its own separate inline-block box and the browser is free to line-wrap between *any* two letters (not just at word boundaries), which produces mid-word breaks like "beyondt" / "he skin" whenever a long heading doesn't fit on one line. The actual reveal-on-scroll is pure CSS: a single shared `IntersectionObserver` in `BaseLayout.astro` (threshold 0.15, fires once) adds `.revealed` to any `.reveal`-classed ancestor, and `global.css`'s `.reveal .letter` / `.reveal .rule-underline` rules key off that one class. `SplashScreen.astro` is the first-visit intro overlay, gated by `sessionStorage` (`samambaia-splash-seen`), same per-letter mechanism but timer-driven instead of scroll-driven.

**Portfolio scroll-zoom effect.** Desktop-only (guarded by `matchMedia('(min-width: 768px)')`), inline `<script>` at the bottom of `index.astro`. Ported directly from the handoff's `onScroll` handler: once the last portfolio tile (`#portfolio-zoom-source`) crosses 55% of viewport height, it "detaches" — a fixed-position clone image (`#portfolio-zoom-clone`, sourced from slot 7's own CMS image, so swapping that photo in Keystatic updates the zoom too) interpolates from the tile's captured bounding rect to full-viewport size over the next `1.1 * innerHeight` of scroll, then crossfades out as `#about`'s top approaches. The original tile is hidden (`opacity: 0`) while the clone is active. This is the single most fragile piece of ported JS in the codebase — if the mosaic layout changes, re-verify `#portfolio-zoom-source` still resolves to the last tile.

**Image pipeline.** Keystatic writes uploads byte-for-byte with no compression. `.github/workflows/optimize-images.yml` runs on every push to `main` touching `public/images/**`, calling `scripts/ci-optimize.sh`, which re-encodes new/changed files to WebP via `scripts/optimize-images.mjs` (using `sharp`) and commits the result back with `[skip-optimize]` in the message to avoid looping — same pipeline as suleika-portfolio, copied verbatim. Expect **two commits and two Cloudflare deploys per CMS image upload**. Collection images live in Keystatic's per-entry layout, `public/images/<collection>/<slug>/image.webp` (each collection has its own `directory`/`publicPath`) — don't point a collection back at the flat `public/images`, or Keystatic stops showing the current photo in the editor and same-numbered portfolio/flash slugs overwrite each other's uploads. Singletons keep flat paths. Intrinsic dimensions are tracked separately in `src/images/sizes.json`/`srcset.json` so `Img.astro`/plain `<img>` tags can set width/height and avoid layout shift. If this repo's GitHub token ever lacks `workflow` scope (as suleika-portfolio's does), a CLI push editing `.github/workflows/**` will be rejected — keep real logic in `scripts/` (the YAML stays a thin wrapper).

**Booking form.** Two instances of the same `src/components/BookingForm.astro` (homepage `#book`, and its own copy at the bottom of `/flash`) post a plain HTML form (no JS required, `enctype="multipart/form-data"` for the optional reference-image upload) to `src/pages/api/contact.ts`. That endpoint reads the `Referer` header to redirect back to whichever page's form was actually submitted (`backPathFrom()`), sends via the Resend HTTP API, and attaches the reference image (if present, ≤5MB, image MIME type — otherwise silently skipped, never fails the whole request) as a base64 attachment. Spam handling is a honeypot field + a minimum-fill-time check + server-side validation, no third-party CAPTCHA. Every check fails open — an uncertain case is delivered rather than dropped, since a lost genuine booking request is worse than an accepted bot. Required env vars: `RESEND_API_KEY`, `CONTACT_TO`, `CONTACT_FROM` (see `.env.example`; in production these are Cloudflare Pages environment variables, set separately for Production and Preview and only effective after the next deploy). Unlike suleika-portfolio, there is no explicit privacy-consent checkbox in the form — that wasn't in the design handoff, and the site's `/privacy` page is linked from the footer instead.

**SEO.** Per-page meta title/description (PT+EN) come from Keystatic (`homepage` and `flash` pages only — this is a single-page site, so most "pages" in the SEO sense are sections, not routes), falling back to `src/seo/defaults.ts`. Canonical URLs, hreflang, Open Graph/Twitter tags, and JSON-LD (`TattooParlor` — schema.org's LocalBusiness subtype, not `Person` like suleika-portfolio, since this reads as a local business search result rather than an artist knowledge panel — WebSite, WebPage, BreadcrumbList, ItemList/ImageObject for the portfolio and flash galleries) are generated in `src/seo/`. `src/pages/sitemap.xml.ts` is hand-rolled since `@astrojs/sitemap` can't work against an SSR-only site with nothing prerendered.

**Fonts.** Cormorant Garamond (italic headings) + Zen Kaku Gothic New (body/UI), self-hosted via `@fontsource/*` using the **`latin-ext`** subset (not plain `latin`) — Portuguese needs the accented characters (ã, ç, é, â, ô...) that `latin-ext` covers and `latin` doesn't. The design handoff used Google Fonts CDN `<link>` tags; self-hosting was a deliberate deviation to avoid a third-party request, matching suleika-portfolio's approach.

**Deployment.** No manual deploy command, once set up — Cloudflare Pages builds automatically on every push to `main` (`wrangler.toml` sets `pages_build_output_dir = "./dist"`). **Not yet connected**: this repo has no GitHub remote and no Cloudflare Pages project as of this writing (see README's "Still open before this can go live"). Cloudflare typically serves old and new code side by side for roughly 90 seconds after a push once deployed, so don't trust an immediate post-deploy check.
